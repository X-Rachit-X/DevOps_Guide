# Code Examples

Two kinds of code live here. Keep them distinct.

| Folder | Origin | Purpose |
|---|---|---|
| [`extracted/`](extracted/) (index: [INDEX.md](INDEX.md)) | **Source-derived.** Every substantial fenced block from the chapters, one file each, generated by `tools/build.py`. | Copy/paste, linting, quick reference |
| [`capstone/`](capstone/README.md) | **Editorial.** A small reference implementation of the Chapter 35 design. | Hands-on practice |

## About the extracted files

- They are **verbatim** from the chapters (minus the `id="…"` attribute some source fences carried). Many are intentionally simplified or contain placeholders (`...`, `<account-id>`), so they will not all run as-is.
- Filenames come from the first line of the block; the extension comes from the fence language.
- Regenerating overwrites the folder: edit the chapter, not the extracted file.
- The audit syntax-checks what can be checked mechanically (YAML parses, JSON parses, `bash -n` for shell). See [AUDIT_REPORT.md](../AUDIT_REPORT.md) for the counts and what was not checked (Terraform, Dockerfiles, TypeScript fragments, Helm templates, Jinja, Jenkinsfiles are not executed).

## About the capstone

See [capstone/README.md](capstone/README.md). TypeScript type-checks and builds; the stack has **not** been run end to end.
